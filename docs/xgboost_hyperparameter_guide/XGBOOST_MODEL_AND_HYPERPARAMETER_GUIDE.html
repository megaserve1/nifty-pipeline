Technical summary

XGBoost repeatedly adds small tree-based corrections to seven class scores. Each proposed split must pass two separate tests: enough statistical evidence (min_child_weight) and enough reduction in the internal training objective (gamma). L1, L2 and max_delta_step control the leaf correction; learning_rate controls how much of that correction is added.

min_child_weightDoes each new child contain enough accumulated Hessian? It is not generally a row count.
gammaDoes this split reduce the regularized training objective enough? It is not accuracy or trading profit.
L2 / reg_lambdaSmoothly shrinks every leaf correction by increasing its denominator.
L1 / reg_alphaSoft-thresholds weak leaf corrections and can make a weak leaf output exactly zero.
subsampleUses a fresh random fraction of training rows in each boosting round. It is not a train/test split.
learning_rateMultiplies each new tree contribution. Smaller steps normally require more boosting rounds.
max_delta_stepCaps a single raw leaf correction before learning-rate shrinkage.
max_binControls histogram split resolution, not tree count, depth, classes or SHAP precision.
Three meanings of “improvement” exist in this pipeline. Tree construction improves weighted training log-loss plus regularization. Early stopping watches weighted validation mlogloss. Optuna ranks completed trials using validation trading_cost. These are related, but not identical.

1. How the seven-class XGBoost model works

Each dataset row is one independent training example containing selected feature values and one label such as ENTRY_SUB, EXIT_SUPER or NO_TRADE. The model keeps seven raw class scores for that row. Softmax converts those scores into seven probabilities that add to one.

1
Start from current class scores. Early in training, scores are close to a common baseline.
2
Measure current mistakes. Weighted multiclass log-loss produces gradients and Hessians.
3
Build correction trees. Candidate feature splits are scored from accumulated gradients and Hessians.
4
Reject weak structure. Child weight, gamma, depth, leaf limits, L1 and L2 act as brakes.
5
Limit and shrink the correction. Delta step caps it; learning rate scales it.
6
Repeat. The next round recalculates gradients and Hessians from updated probabilities.
Tree-count meaning: n_estimators=6000 means at most 6,000 boosting rounds—not simply 6,000 physical trees. With one output tree per class and seven classes, the ceiling is approximately 42,000 physical trees. Early stopping normally reduces the number used for prediction.

2. What the model is actually optimizing

XGBoost balances predictive fit against tree complexity:

Objective = weighted multiclass log-loss + gamma × number_of_leaves + 0.5 × reg_lambda × Σ(leaf_score²) + reg_alpha × Σ|leaf_score|
PartPlain meaningControlled by
Weighted multiclass log-lossHow strongly seven probabilities disagree with the true class after row/class weights.objective, data and sample weights
Tree-size costA fixed price for additional terminal leaves.gamma
Squared leaf penaltyContinuous pressure against large leaf corrections.reg_lambda / L2
Absolute leaf penaltyThreshold pressure that can zero a weak leaf correction.reg_alpha / L1
The model does not directly optimize trading cost. Trading cost is calculated after prediction and is used by Optuna to compare completed trials. Inside each tree, split gain comes from weighted multiclass logistic loss plus regularization.

3. Gradient and Hessian: the two statistics used everywhere

StatisticEasy meaningRole
Gradient, gDirection and strength of the correction needed for a class score.Pushes a leaf score up or down.
Hessian, hCurvature of the loss around the current prediction.Acts as second-order statistical mass in leaf values, split gain and min_child_weight.
gradient(i,c) = sample_weight(i) × [ probability(i,c) − indicator(true_class = c) ] hessian(i,c) ≈ 2 × sample_weight(i) × probability(i,c) × [1 − probability(i,c)]

The class-based sample weight multiplies both statistics. High-weight rare-class rows therefore influence split eligibility and leaf corrections more strongly than low-weight rows.

Hessian is not row count and not simply raw sample-weight sum. It depends on both the weight and the current class probability, so it changes throughout training.

4. min_child_weight: “Is there enough evidence?”

A proposed left and right child must both contain enough accumulated Hessian:

H_left = Σ hessian values in proposed left child H_right = Σ hessian values in proposed right child Required: H_left ≥ min_child_weight H_right ≥ min_child_weight

Your effective value is min_child_weight=48.

Rejected example
H_left = 70 H_right = 30 minimum = 48

The right child fails, so the split is rejected even if it contains many physical rows.

Eligible example
H_left = 70 H_right = 55 minimum = 48

Both pass this gate. The split must still pass the separate gamma gain test.

Why there is no fixed row equivalent

At the initial seven-class probability of approximately 1/7, the Hessian is roughly 0.245 × sample_weight. At that moment only, reaching H=48 could require:

Illustrative row typeSample weightApproximate rows
Unit-weight row1196
ENTRY_SUB1911
NO_TRADE0.1921,021

These are illustrations, not permanent conversions. Probabilities change after every round; real leaves mix classes; each class has a separate correction tree.

Higher values block small or low-information branches and reduce overfitting. A value that is too high can stop genuine rare-class structure.

5. gamma: “Is the split beneficial enough?”

After a candidate passes the Hessian gate, XGBoost compares two new children with the original parent. Without showing L1 in the notation, the official gain formula is:

Gain = 0.5 × [ G_left² /(H_left + lambda) + G_right²/(H_right + lambda) − (G_left + G_right)²/(H_left + H_right + lambda) ] − gamma

Your effective value is gamma=0.3. A split is accepted only when final gain is positive.

Raw objective reductiongammaFinal gainDecision
0.800.30+0.50Accept
0.200.30−0.10Reject
“Improvement” is not a percentage. It is the estimated reduction in XGBoost’s regularized weighted training objective. It is not accuracy, macro-F1, validation trading cost, SHAP importance or backtest return.
QuestionParameter
Does each child contain enough accumulated statistical mass?min_child_weight
Does the eligible split improve the objective enough after penalties?gamma

6. L1 and L2 regularize leaf scores—not feature columns

For one proposed leaf, let G be summed gradients and H be summed Hessians.

leaf_score = −G / (H + reg_lambda)

L2 — reg_lambda

Your effective value is reg_lambda=10. L2 increases the denominator and smoothly shrinks every correction.

Example: G = −20, H = 10 lambda = 0 → leaf_score = 2.0 lambda = 10 → leaf_score = 1.0

L2 is strongest proportionally on low-H leaves. It also lowers split gain. It normally makes leaf values smaller rather than exactly zero.

L1 — reg_alpha

Your effective value is reg_alpha=0.2. L1 first soft-thresholds G:

S(G, alpha) = sign(G) × max(|G| − alpha, 0) leaf_score = −S(G, alpha) / (H + lambda)
Example: G = −20, H = 10, lambda = 0 alpha = 0 → leaf_score = 2.0 alpha = 5 → leaf_score = 1.5 alpha = 20 → leaf_score = 0.0
PropertyL2 / reg_lambdaL1 / reg_alpha
PenaltySquared leaf scoreAbsolute leaf score
BehaviourSmooth shrinkageThreshold plus shrinkage
Can zero a weak leaf?Normally noYes
Directly removes an input feature?NoNo
The phrase “L1 prunes useless features to zero” is inaccurate for a tree booster. L1 can zero a weak leaf correction; it does not assign and remove one global coefficient per feature.

7. Learning rate, estimator count and early stopping

learning_rate / eta

Your effective value is learning_rate=0.02.

new_class_score = old_class_score + learning_rate × new_tree_correction
Raw correction = 1.0 learning_rate = 0.02 added contribution = 0.02

This does not mean 2% of rows, 2% of features, or 2% better accuracy. It means each new tree contributes only 2% of its calculated raw correction. The next round recalculates errors.

n_estimators

n_estimators=6000 is the maximum number of boosting rounds. Lower learning rates normally need more rounds. Searching learning rate and round count independently creates unfair pairs; 0.002 with only 2,000 rounds may be strongly underpowered.

early_stopping_rounds

Your effective patience is 200. Training stops after 200 consecutive rounds without improvement in weighted validation mlogloss. Normal sklearn prediction uses best_iteration, although the stored booster can retain later patience trees.

Treat estimator count as a high ceiling when early stopping is active. Log best_iteration. If every trial stops below 2,000, comparing ceilings of 2,000, 4,000 and 6,000 is mostly wasted search.

8. Row sampling and feature sampling

subsample: rows per boosting round

Your effective value is subsample=0.6.

Round 1: draw about 60% of training rows and build correction trees Round 2: draw a fresh sample; skipped rows can return Round 3: draw again, and continue

This adds randomness, reduces dependence on individual rows and can reduce memorisation. It does not permanently discard 40% of the data and is not a train/test split. With uniform sampling, class weight affects the loss after a row is selected—not its chance of selection.

Column sampling: which features can compete

ParameterWhen sampling occursCurrent
colsample_bytreeOnce for each physical tree0.6
colsample_bylevelAgain at each depth level1.0
colsample_bynodeAgain at every split0.5
Effective availability per split ≈ 0.6 × 1.0 × 0.5 ≈ 0.30, or 30% of all features

With 16 features, roughly five can compete at one split. Sampling helps stop a single feature from monopolizing every node, but it cannot repair leakage or several duplicated proxy features.

subsample randomizes training rows. colsample_* randomizes available features. Neither changes the label definition or repairs a leaking validation design.

9. Tree shape: grow_policy, max_depth and max_leaves

ControlMeaningCurrent
grow_policylossguide grows the available leaf with greatest loss reduction; depthwise grows near-root levels.lossguide
max_depthMaximum decisions on one root-to-leaf path.8
max_leavesMaximum terminal regions in one tree.256

Loss-guided growth can be irregular because it repeatedly follows the current highest-gain leaf. Depth prevents a very long rule chain; leaf count prevents too many terminal regions overall.

A full balanced binary tree of depth 8 can contain: 2⁸ = 256 leaves

The current depth cap already creates a theoretical 256-leaf ceiling. The two limits are still conceptually different: an uneven tree may hit depth 8 with far fewer than 256 leaves.

These are the most direct capacity controls, but the current HPO space searches neither. HPO therefore optimizes brakes around a fixed tree shape.

10. max_delta_step: maximum steering movement

Your effective value is max_delta_step=1.

Calculated raw leaf correction = 4.5 max_delta_step = 1.0 capped raw correction = 1.0 learning_rate = 0.02 added class-score contribution ≈ 0.02

It is useful when class imbalance or heavy sample weights could create a violent update. It caps one raw leaf correction; it does not cap cumulative prediction over thousands of trees. A value of zero means no cap.

Softmax converts all seven raw scores together. A +0.02 raw class-score change is not necessarily a +2 percentage-point probability change.

11. max_bin: histogram split resolution

Your model uses tree_method="hist" and max_bin=256. Continuous values are grouped into numeric histogram bins, and split search tests bin boundaries rather than every raw value repeatedly.

Setting directionEffectTrade-off
Smaller max_binCoarser candidate thresholdsFaster, lower memory, sometimes regularizing
Larger max_binFiner candidate thresholdsMore memory/compute; may find a more precise split
It does not mean 256 leaves, classes or rows. It means at most 256 histogram buckets for a continuous feature.

If a feature has only 16 distinct ordered bucket values, increasing 128 to 256 or 512 normally creates no extra unique boundaries for that feature. Higher values do not automatically overfit; the primary documented trade-off is split resolution versus computation.

15. Feature dominance: which controls actually help?

ControlHow it affects dominanceWhat it cannot prove
colsample_bytreeMakes a feature unavailable to some entire trees.Whether the feature is leakage.
colsample_bynodeMakes a feature unavailable at some split decisions.Whether correlated copies carry the same signal.
feature_weightsCan lower a named feature selection probability.Whether down-weighting is scientifically justified.
Depth and leaf capsLimit increasingly specific repeated rules.Whether the original feature is valid.
Child weight and gammaRequire evidence and gain for niche splits.Whether a feature encodes future information.
L1, L2 and delta stepShrink or cap leaf effects after a feature is used.Feature causality.

A dominant feature is not automatically wrong. Validate it with:

  1. Split count, gain, total gain, cover and total cover.
  2. SHAP share and top-five frequency across samples and seeds.
  3. Performance after removing that feature.
  4. Performance after removing its correlated feature family.
  5. Exact and near-duplicate-column checks.
  6. Forward out-of-sample performance.

18. Important limitations and review warnings

  1. Objective mismatch: early stopping chooses a round using weighted validation mlogloss; Optuna chooses a trial using validation trading_cost.
  2. Test exposure: Optuna reads validation cost, but the trainer still calculates and displays test metrics for each trial. The test is therefore visible before final selection.
  3. Categorical meaning: ordered buckets can be numeric codes. Unordered categories encoded as integers create a false order that HPO cannot repair.
  4. Stale comments: descriptions of child weight as raw weight sum and L1 as direct feature pruning are inaccurate.
  5. Base-task freshness: ClearML trials clone a registered code/configuration snapshot. Re-register after fixed code or configuration changes.
  6. Validation design: bundle-random assignment keeps a 15-minute bundle together but does not create an embargo around scattered validation/test bundles. Confirm finalists on forward OOS data.

19. Common code-review questions

QuestionShort correct answer
What improvement does gamma measure?Reduction in the approximate regularized training objective—not accuracy or profit.
Is min_child_weight a row count?No. It is minimum summed Hessian; probability and sample weight change its row-equivalent.
Difference between child weight and gamma?Child weight asks “enough evidence?”; gamma asks “enough benefit?”
Does L1 remove features?No. It soft-thresholds leaf scores and can zero weak leaf corrections.
What does learning_rate=0.02 mean?Each new tree contributes 2% of its raw correction.
Why can 6,000 estimators become 42,000 trees?Seven-class one-output-per-tree boosting creates about seven physical trees per round.
Does subsample=0.6 discard 40% permanently?No. A fresh 60% sample is drawn each boosting round.
What does max_delta_step=1 cap?One raw leaf correction—not the total prediction or tree count.
What does max_bin=256 control?Histogram resolution for continuous split candidates.
Why is max_bin low-priority?If features have only about 16 values, all searched bin counts already exceed available thresholds.
Main lossguide capacity knob?max_leaves, with max_depth as a safety cap.
Which knob controls a dominant feature?Column sampling reduces opportunity; feature weights change sampling probability. Neither validates the feature.

Further questions

  • Are all bucket codes genuinely ordered, or are some nominal categories?
  • At which round does trading cost reach its minimum relative to validation mlogloss?
  • Do current trees commonly hit depth 8, leaf count 256, or neither?
  • Does removing the dominant feature family preserve forward performance?
  • Does the HPO winner remain best across several bundle assignments?
